# Безопасность MyVoyage

Приложение офлайновое и однопользовательское: аккаунтов, сервера и чужих
данных нет. Поэтому модель угроз сводится к трём вещам.

1. **Ключ подписи.** Утечка `myvoyage-release.jks` = приложение больше нельзя
   безопасно обновлять, а чужой человек может выпустить «обновление» от вашего
   имени. Отозвать ключ нельзя.
2. **Данные на устройстве.** База `myvoyage.db` — это финансовая история:
   рейсы, расходы, топливо, офисы, машины.
3. **Один внешний запрос.** Курсы валют НБМ (`bnm.md`). Ответ приходит извне,
   значит ему нельзя доверять по умолчанию.

## Что сделано

| Мера | Где | От чего защищает |
|---|---|---|
| `*.jks`, `*.keystore`, `keystore.properties` в `.gitignore` | `.gitignore` | утечка ключа подписи в публичный репозиторий |
| CI-проверка индекса + gitleaks по всей истории | `.github/workflows/security.yml` | тот же случай, но когда `.gitignore` обошли (`git add -f`) |
| `android:allowBackup="false"` | `AndroidManifest.xml` | выгрузка базы расходов в облако Google и `adb backup` |
| Явные `<cloud-backup>` / `<device-transfer>` | `res/xml/data_extraction_rules.xml` | то же на Android 12+, где `allowBackup` уже не решает всё |
| `cleartextTrafficPermitted="false"`, доверие только системным CA | `res/xml/network_security_config.xml` | перехват трафика (MITM) через пользовательский сертификат |
| `HttpsURLConnection` + лимит 1 МБ на ответ | `data/remote/BnmRatesService.kt` | запрос в открытую, исчерпание памяти подменённым ответом |
| Отчёты только в приватном `filesDir`, наружу — через `FileProvider` | `export/ExportCache.kt`, `res/xml/file_paths.xml` | чтение сгенерированных PDF/XLSX другими приложениями |
| `isDebuggable = false` в release | `app/build.gradle.kts` | чтение памяти и базы через `adb` на боевой сборке |
| R8 (`isMinifyEnabled`, `isShrinkResources`) | `app/build.gradle.kts` | упрощённый реверс-инжиниринг APK |
| Экспортирована только `MainActivity`, `FileProvider` не экспортирован | `AndroidManifest.xml` | запуск внутренних экранов и чтение файлов чужим приложением |
| Отчёты отдаются через `FileProvider` с `FLAG_GRANT_READ_URI_PERMISSION` | `export/ReportSharing.kt` | доступ к файлам шире, чем на один шаринг |

## Правила работы с ключом подписи

- `myvoyage-release.jks` и `keystore.properties` **никогда** не коммитятся.
  Проверить перед пушем: `git status --porcelain | grep -Ei 'jks|keystore'`.
- Держите копию ключа и паролей в менеджере паролей или на офлайн-носителе.
  Потеря ключа так же фатальна, как утечка: обновить приложение будет нечем.
- Если ключ всё-таки попал в публичную историю — считайте его
  скомпрометированным. Сгенерируйте новый и раздайте друзьям новый APK
  (установить поверх старого не получится — подпись другая).

## Раздача APK друзьям

Отправлять можно **только** release:

```
./gradlew assembleRelease
# app/build/outputs/apk/release/app-release.apk
```

Debug-сборка в этом проекте подписана тем же боевым ключом (сделано намеренно,
чтобы сборка из Android Studio вставала поверх release и не стирала базу).
Из-за этого debug-APK одновременно подписан «по-настоящему» и допускает
отладку — из него можно вычитать всю базу расходов. Наружу он не уходит.

## Что осознанно НЕ сделано

- **Шифрование базы (SQLCipher).** База и так лежит в приватном каталоге
  приложения, недоступном другим приложениям; шифрование помогает только
  против физического доступа к разблокированному или рутованному телефону.
  Цена — +3–4 МБ к APK и миграция существующих данных.
- **Блокировка по биометрии.** Тот же сценарий: защищает, если телефон
  разблокирован и в чужих руках.
- **Certificate pinning для bnm.md.** Пиннинг ломается при плановой смене
  сертификата на стороне банка, а данные там публичные и не секретные —
  доверия системным CA достаточно.
- **Автоудаление старых отчётов.** Сознательное решение в пользу сохранности
  данных: сгенерированные PDF/XLSX копятся в `filesDir/exports` и не
  удаляются. Каталог приватный, поэтому риск — только физический доступ
  к разблокированному телефону. Если понадобится, отчёты чистятся через
  «Настройки → Приложения → MyVoyage → Очистить данные» (вместе с базой).
